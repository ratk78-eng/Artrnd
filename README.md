# kompas-mcp — локальный MCP-сервер для КОМПАС-3D

Работает полностью на этом компьютере: Python управляет КОМПАС-3D v23 через COM API.
Никакого облака, регистрации и отправки данных наружу.

## Требования

- Windows, КОМПАС-3D v23 (проверено на 23.0.3.2285)
- Python 3.10+ и библиотеки из `requirements.txt`:

```
python -m pip install --user -r requirements.txt
```

## Подключение

**Claude Code** (папка `D:\KOMPAS-3D v23 x64`): уже подключено файлом `..\.mcp.json`.
При первом запуске сессии в этой папке Claude спросит, доверять ли серверу `kompas-3d`.

**Claude Desktop** (`%APPDATA%\Claude\claude_desktop_config.json`), **Cline, Roo Code и др.**:

```json
{
  "mcpServers": {
    "kompas-3d": {
      "command": "C:/Python/python.exe",
      "args": ["D:/KOMPAS-3D v23 x64/kompas-mcp/server.py"]
    }
  }
}
```

**Codex** (`%USERPROFILE%\.codex\config.toml`):

```toml
[mcp_servers.kompas_3d]
command = "C:/Python/python.exe"
args = ["D:/KOMPAS-3D v23 x64/kompas-mcp/server.py"]
tool_timeout_sec = 300
```

Файлы, сохранённые по относительному пути, попадают в `Документы\kompas-mcp`
(можно поменять переменной окружения `KOMPAS_MCP_OUT`).

## Установка на другой компьютер

Готовый установщик: `dist\KompasMCP-<версия>-Setup.exe` (собирается командой
`powershell -ExecutionPolicy Bypass -File installer\build_installer.ps1`, нужен только Windows).

Установщик работает без прав администратора и ставит программу в
`%LOCALAPPDATA%\Programs\KompasMCP`: проверяет КОМПАС-3D, находит Python 3.10+ (если его нет —
предлагает поставить через winget), ставит библиотеки через pip (нужен интернет), создаёт ярлыки
и пункт «KOMPAS MCP» в «Приложениях» Windows для удаления. Настройки прошлой версии сохраняются.
Файл не подписан, поэтому Windows SmartScreen может предупредить: «Подробнее → Выполнить в любом случае».

## Программа для Windows

Один раз создайте ярлыки «KOMPAS MCP» на рабочем столе и в меню «Пуск»:

```
powershell -ExecutionPolicy Bypass -File install_shortcut.ps1
```

Ярлык запускает `KompasMCP.pyw` без консоли: поднимается сервер интерфейса и открывается
отдельное окно программы (Edge в режиме приложения, со своим профилем). Закрыли окно — сервер
остановился. Журналы: `%LOCALAPPDATA%\kompas-mcp\app.log` и `server.log`.

## Чертежи PDF

Кнопка 📎 в чате или перетаскивание файла в окно: PDF, PNG, JPG. PDF разбивается на листы
встроенным в Windows механизмом (`ui\pdf2png.ps1`), листы показываются миниатюрами — щелчком
выберите нужные. Выбранные листы уходят модели как изображения, поэтому нужна vision-модель
(в LM Studio у таких моделей есть файл `mmproj`). Загрузки хранятся в `%LOCALAPPDATA%\kompas-mcp\uploads`.

## Веб-интерфейс и локальные LLM

```
start_ui.bat          (или: python ui\app.py)
```

Откроется http://127.0.0.1:8765: чат в центре, настройки модели и статус КОМПАС в боковой панели.
Модель подключается по OpenAI-совместимому API и сама вызывает инструменты сервера (tool calling);
вызовы, их результаты и скриншоты видны прямо в чате.

| Сервер | Адрес API | Что сделать |
|---|---|---|
| LM Studio | `http://127.0.0.1:1234/v1` | Developer → Start Server, загрузить модель. Если включено «Require API token» — вписать токен в поле «API-ключ» |
| Ollama | `http://127.0.0.1:11434/v1` | `ollama serve`, `ollama pull qwen3` |
| llama.cpp | `http://127.0.0.1:8080/v1` | `llama-server -m model.gguf --jinja` |

Нужна модель с поддержкой вызова инструментов (Qwen3, Gemma 4, Llama 3.1+, Mistral и т.п.).
Флажок «Показывать модели скриншоты» отправляет снимки модели обратно в LLM — только для vision-моделей.
Настройки хранятся в `ui\settings.json`.

Проверка без настоящей LLM (подставная модель вызывает инструменты): `python tests\ui_test.py`.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `diagnostics` | Запущен ли КОМПАС, открытые документы, активный документ |
| `launch_kompas` | Запустить КОМПАС или подключиться к запущенному |
| `build_part` | **Главный**: вся деталь одним вызовом по списку операций (выдавливание, вырез, вращение), сверка объёма, снимок |
| `new_part` | Новая 3D-деталь |
| `sketch` | Эскиз на XY/XZ/YZ (со смещением): прямоугольники, окружности, отрезки, ломаные, дуги, осевые |
| `extrude` | Выдавливание / вырез (на глубину, насквозь, симметрично) |
| `revolve` | Вращение вокруг осевой линии (примитив со `style: 3`) |
| `plate_with_holes` | Готовая пластина с 4 отверстиями по углам |
| `model_info` | Объём, площадь, масса, центр масс, дерево построения |
| `new_fragment`, `draw_2d` | 2D-фрагмент/чертёж и примитивы с текстом |
| `save` | Сохранить .m3d / .frw / .cdw |
| `export` | STEP, IGES, STL, Parasolid, DXF, DWG, PDF, PNG/JPG — по расширению |
| `set_view`, `screenshot` | Ориентация (изометрия, спереди, сверху…) и снимок модели |

Вложенные замкнутые контуры в одном эскизе дают отверстия: так строится пластина
одним выдавливанием.

Координаты эскиза «естественные»: на XY — (X, Y), на XZ — (X, Z), на YZ — (Y, Z); offset и
выдавливание идут по нормали +Z, +Y, +X (`tests\plane_axes.py`).

Почему `build_part`: каждый шаг агента — это заново прочитанный запрос и новые рассуждения модели.
Деталь, построенная одним вызовом, занимает 1–2 шага вместо 6–10. Сервер сам подсказывает модели,
что пошло не так: операция ничего не изменила, бобышка «ушла» в тело (забытый offset), не задана глубина,
объём не совпал с ожидаемым.

## Пример запроса

> Создай пластину 100 × 60 × 5 мм с четырьмя отверстиями Ø4 в 8 мм от краёв,
> добавь сверху бобышку Ø20 высотой 10 мм, сделай скриншот и экспортируй в STEP.

## Проверка

```
python tests\smoke_test.py
```

Тест запускает сервер по протоколу MCP (stdio), строит пластину, вал и 2D-фрагмент,
сохраняет и экспортирует их в `Документы\kompas-mcp\smoke`.

## Как устроено

- `kompas_api.py` — обёртка над API5/API7 КОМПАС (раннее связывание через библиотеки типов `kAPI5.tlb`, `kAPI7.tlb`).
- `server.py` — MCP-сервер (`mcp` 2.x, `MCPServer`). Все обращения к COM идут через один поток,
  потому что COM-объекты КОМПАС привязаны к своему потоку.

Чтобы добавить новую операцию (фаска, скругление, массив, сборка), допишите метод в `Kompas`
и тонкую обёртку-инструмент в `server.py`.
